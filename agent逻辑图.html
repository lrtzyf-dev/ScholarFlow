研序 ScholarFlow · Agent 实现逻辑
单 Agent · ReAct 式「规划—执行—取证」循环 + 引用闸门（Critic）；过程经 SSE 实时推送
用户提问
问题文本 + 可选范围（paper_id：单篇提问 / 留空：全库检索）
▼
Agent 核心循环 · 最多 6 轮（max_agent_steps）
LLM 决策（System Prompt + 工具定义）
规则：事实问题必须先检索；只能基于证据作答；每句论断标 [^eN]；证据不足则拒答
工具 retrieve_evidence（检索原文证据） 工具 list_papers（列出论文）
▼
返回工具调用 → 执行工具
retrieve_evidence → 混合检索
FTS5 / BM25 + 向量检索 → RRF 融合
证据包：页码 + bbox + 原文片段 + 相关度；无 embedding Key 时向量走本地哈希
list_papers → 返回已解析论文清单
无工具调用 → 直接产出答案
模型认为无需检索（如已在上下文中），以当前内容作为候选答案，退出循环
把工具结果作为 tool 消息追加，回到 LLM 继续决策
▼
引用闸门（Critic）
每个实质论断（≥10 字）必须带有效 [^eN]；不允许超出证据范围的无效标记
不通过 → 真实模型重写 1 次 仍失败 → 拒答 通过 → 进入交付
▼
落库 + 交付
问答记录（QARecord：答案/论断/耗时/过程）写入数据库；SSE 推送 answer、done 事件
SSE 事件流（前端过程面板按序渲染）
status → plan → step → tool_call → tool_result → critic → answer → done
