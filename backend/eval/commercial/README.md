# 正式真实模型验收清单与执行器

`manifest.json`含60个不同用户目标，来源为可审阅的`case_manifest.py`。覆盖12个日常多轮、12个来源任务、10个科研工作流、14个纠偏/权限/恢复、6个成果和6个模型工具任务。它是待执行清单，不是60条已通过记录，也不把旧7条真实抽验自动搬入本套分数。

所有资料由测试生成，明确标为虚构验收材料；模型及启用的工具响应必须来自实际配置的服务。不会打开用户文献库、复制用户材料或记录模型私有推理。模型凭证优先从当前Windows用户可解密的受保护配置读取；在用户已授权的旧配置仅有明文模型密钥时，允许只读到内存用于本次评测，报告以`credential_storage_kind`标明旧配置待迁移。受保护字段只要存在，格式或解密失败均会阻断，不能降级使用旧密钥。脚本不接受命令行明文密钥，不写回或迁移原配置，不将密钥写入报告。

## 默认只生成计划

在backend目录运行：

```powershell
.\.venv\Scripts\python.exe scripts\verify_real_acceptance.py --report ..\verification\real-acceptance-v1\plan.json
```

默认不读凭证、不访问网络。可用`--case DOC05 --case ART02`缩小计划。清单检查目标/输入唯一和具体验收，不用同题改数字增加样本数量。重新生成清单：`python eval/commercial/case_manifest.py`。

## 真实运行采用固定副本和小批

先用`freeze_real_evaluation.py`把代码、两个清单文件、运行和评审脚本纳入同一固定副本；安装包、用户原件、配置、DB和虚拟环境不属于代码副本。使用已有虚拟环境执行副本脚本时，模块路径指向副本backend。复制前后及运行前后的SHA核对必须保留。源文件发生变化的批次不能直接签收。

第一批建议选择与既有普通聊天/固定TXT/框架抽验不同的五个目标：

| ID | 目标 | 单目标建议请求预算 |
|---|---|---:|
| RESEARCH02 | 正式持久翻译，保留公式与代码 | 3 |
| RESEARCH04 | 指令形原文仅翻译，不成为权限 | 3 |
| DOC12 | 两份资料的冲突证据与引用 | 6 |
| DOC05 | XLSX单位、单元格及空公式缓存 | 6 |
| ART02 | 仅结论章节的待审修改差异 | 6 |

可一批指定五个`--case`，`--max-calls 32`是整个评测进程的HTTP尝试上限；默认6，允许1至32。实际HTTP尝试与模型计量尝试分开记账，真实用量、已知/未知金额和单任务耗时分别保存。此上限只约束有收费风险的评测，不改变产品的持续执行规则。总预算耗尽的案例记未执行，不计通过。真实执行必须显式提供`--run-real --credentials-dir <受保护APPDATA目录>`；一次最多5个明确选择的案例。

第二批优先CONTROL06/07/08、CONTROL09/10/11、CONTROL13/14，并逐条检查控制确实发生。任务过快未送入纠偏、未实际停止、未知请求没有完成核对，都记`not_exercised`或失败，不伪称恢复已验收。脚本不自动重试未知收费请求。真实进程崩溃、断网、跨窗口和长时间运行仍需另行故障注入与原生宿主验收，不能由HTTP观察替代。

随后运行全部六格式、跨来源、矩阵、成果与联网任务，并在另一实际供应商重复适用目标。`--provider-role second`必须使用另一HTTPS端点的受保护配置；端点不同不自动证明底层模型身份，仍须核实供应商。未配置第二供应商时明确缺失，不使用合成模型替代。

## 独立工具的真实配置

Search/Fetch/OCR与聊天凭证独立。需要额外明确指定`--allow-paid-tools --service-config-db <受保护APPDATA目录内的DB>`。脚本用只读SQLite连接仅查询`service_tool_configurations`和`service_tool_credentials`两张表，解密后在隔离库通过正式配置API重建已启用服务，不读取资料/会话表。不会借用模型密钥，也不复制整个用户DB。凭证无效、服务缺失或未单独选择时，相应案例记录受阻。

实际发送只允许所选模型主机及明确配置的DeepSeek服务主机，且不跟随重定向。未知外部工具不会自动批准。写入仅允许测试所需的可编辑成果/证据矩阵工具；命令和项目文件写入没有自动授权。工具能力与实际调用成功仍须分别验收，模型说“已联网”不算回执。

## 输出和签收

运行报告保留每轮公开答案、实际工具名称、可解析引用、固定材料SHA及版本、持久Run、成果当前版本和待审差异、矩阵、复算结果与分任务用量。公开`critic/audit/refuse/error`仅保存白名单诊断字段；评测进程临时包装原引用闸门，按同一run_id保留送审的公开候选答案与机械检查结果，包含重写稿，并在finally恢复原函数。不会截获模型原始响应、thought/reasoning或provider_context。正常案例必须有非拒答的完整结果；部分完成、受阻或仅有一段拒答文本不能通过机械完成条件，只有显式取消案例可用已确认取消回执，显式计划案例可用真实计划。临时运行库销毁后仍能逐项语义审查。私有思考链、原始配置和凭证不进入报告。

机器检查只做结构、数值线索、实际工具回执、来源解析及副作用核实，不能凭关键词替代全文正确性。即使机器全过也只记`needs_semantic_review`，`passed=false`。

`review_real_acceptance.py`接受显式评审JSON，必须包含`reviewer`、`reviewer_kind`（`human`或`agent`）、`independent_review_attestation=true`、`case_id`、`decision`及与原验收文本逐条一致、每条有理由的`rubric`。原运行报告和评审文件保持原样，另存带二者SHA的结果。

Agent工程/语义复核记入`agent_review`，不能成为人工金标或正式accepted；正式human审阅才可签收所选案例。受阻、未执行、机器失败或源文件变动不能签收通过。单批即使全部人工通过也不是完整60案例、双供应商、8位目标用户、科研人工金标或Windows发行通过；`commercial_acceptance`始终为false，由总发行门槛另行裁决。

## 当前证据边界

当前本套只做清单、执行器机制和默认计划验证，没有发出收费请求。`verification/real-acceptance-v1/harness.xml`是执行器机制测试，使用明确合成响应；不能算作60个真实模型任务的执行结果。历史真实模型报告单列于`verification/real-model-20261116/`，按其冻结代码身份和任务范围解释，不能自动套用到本套当前源码。
