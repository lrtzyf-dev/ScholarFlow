Agent 调用大模型检索文档库 · 实现链路
两次调用大模型：第 1 次让模型决定"查什么"，第 2 次让模型基于"查到的证据"作答
大模型做的事 程序代码做的事
①
第 1 次请求大模型：把「工具定义」一起发过去
POST {base}/chat/completions，messages = 系统规则 + 用户问题；body 里带两个 function 工具（retrieve_evidence、list_papers）
▼
②
模型返回工具调用，并自己「改写检索词」
tool_calls = retrieve_evidence，参数 arguments 里的 query 由模型从问题提炼（补术语/标题/数字），还可指定 k、paper_id
用户问："它效果比老方法好多少？" → 模型改写 query："Transformer BLEU 41.8 对比 baseline 循环神经网络"
▼
③
程序执行 retrieve：混合检索（候选量 = topk × 4）
路 A · 关键词（FTS5 / BM25）
query 拆成英文单词 + 中文单字，OR 匹配 chunks_fts，按 BM25 相关度排序（中文已按字展开）
路 B · 语义（向量）
query 编码成向量，与 numpy 向量库矩阵做点积取余弦；无 Key 时用本地哈希向量
RRF 融合：score = Σ 1/(60 + 名次 + 1)，两路合并取 topk
兼顾「精确关键词命中」与「语义相近命中」；命中后截取含检索词的窗口，打包成证据包
▼
④
证据包 Evidence（编号 e1…eN 此刻确定）
页码 page 位置 bbox 原文 quote 相关度 score 所属论文
页码 + bbox 可在阅读器定位并高亮原文；这些 id 就是答案里 [^eN] 的合法范围
▼
⑤
第 2 次请求大模型：把证据作为 tool 消息喂回去
模型只基于这些证据组织自然语言答案，每句论断标注对应 [^eN]；之后再过引用闸门
无 Key 离线时：MockLLM 第 1 轮强制返回 retrieve_evidence（query 直接用原话），同样走混合检索，第 2 轮用证据模板拼答案——检索链路与真实模型完全一致，可离线演示。
