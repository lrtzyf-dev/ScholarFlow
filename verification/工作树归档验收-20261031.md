# Windows 桌面：工作树快照归档

本批补齐未提交内容的归档与恢复。范围仍为 Windows 桌面 1440×900、1100×700。验收包：`研序ScholarFlow-桌面验收版-20261031-工作树归档.zip`，程序位于 `ScholarFlow/ScholarFlow.exe`。

## 使用

1. 打开“项目文件 → 工作树”，选择应用创建的工作树，点击“审阅归档”。
2. 查看文件数量、总大小和文件范围。未提交修改及非 ignored 未跟踪文件进入 Git 快照；被忽略文件只进入本机 ZIP，不写入 Git 历史。
3. 点击“保存快照并归档”。先保存可恢复的提交和字节备份，再移除工作目录。原分支不推进，原暂存版本另存为快照的父提交。
4. 在“已移除”中恢复工作树，原项目和会话继续可用。恢复后使用分离 HEAD，本地修改已包含在快照提交中，不重新拆分原暂存/未暂存状态。
5. “下载本机备份”可保存完整工作文件、文件哈希清单和原索引记录。ZIP 的 `files/` 保留归档时的原始字节；它不是完整 Git 仓库备份，提交历史仍依赖来源仓库。

原有“审阅移除”继续仅接受干净目录。需要保存未提交内容时使用“审阅归档”。

## 关键保护

- 对文件哈希、暂存区、HEAD、分支、目录身份和配置做审阅快照。确认时或保存过程中发生变化就停止，不用旧审阅移除目录。
- Git 快照通过临时索引建立；原暂存内容另存提交，本机备份完成并同步到磁盘后才修改工作树状态。快照使用应用自身的作者标识，原分支不变。
- 准备移除时，仅将当前工作树的 HEAD 分离到快照；不使用强制工作树移除。被忽略文件在核对备份和当前字节后按文件移除，每个文件先保存恢复记录。
- 活动任务/终端、子模块、嵌套仓库、Git 锁、合并/变基状态、跳过检查的索引标记、链接或目录联接均拒绝。
- 恢复前验证 ZIP 的 SHA256；通过无检出工作树及原始字节备份恢复，避免 checkout 过滤器或换行转换改变原文件。恢复中断可补齐缺失文件，存在不同内容或新的暂存改动时停止并保留现场。
- 归档移除失败时，核对恢复可重新接入原目录，补回本批已移走的忽略文件；已有的后来修改不会被覆盖。若已分离到快照，则继续保留该 HEAD 和原分支，提示用户核对后继续工作。

## 对标与剩余差距

当前 Codex 应用暴露的 `archive_worktree` 说明会在移除前保存本地修改、未推送提交、非 ignored 未跟踪文件；`restore_worktree` 恢复原路径的分离 HEAD，未提交内容成为快照提交。这一核心流程本批已实现。研序另外自动把忽略文件保存在本机 ZIP 中，不将它们加入 Git 历史；这是研序的保存策略，不是对 Codex 内部实现的推断。

归档最多 10,000 个普通文件、512 MiB 原始内容、64 层目录，包含忽略文件。超限需先移出大型缓存。目录链接、ACL、空目录、时间戳和完整 Git 仓库备份不在本批恢复承诺内；恢复依赖原来源仓库与本机归档记录。快照建立遵循本机 Git clean 过滤器，不能保证与任意外部 Git 或文件写入完全隔离。现已提供桌面快照历史列表、ZIP 校验状态和非当前快照单项清理；仍无自动保留策略、批量清理和快照内容对比。
