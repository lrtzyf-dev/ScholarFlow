# 终端隔离桌面验收 · 2026-10-31

本批处理清单外的桌面稳定性问题。仅 Windows 桌面端，验收尺寸为 1440×900、1100×700。

## 发现与改动

上一批全量测试停滞，已停止并保留原日志。本次逐项诊断完成 444 项：443 通过，1 项失败来自测试先观察到状态变化、再立即断言工作线程已经退出的竞态；实际退出码为 7，符合预期。现已等待线程结束再验证。

对终端 HTTP 创建/关闭流程重复运行时，再次出现长时间停滞。`terminal-http-stress-diagnostic.log` 和 `terminal-thread-state.log` 显示请求停在 Python Thread.start 的事件等待，目标线程已开始且事件标记已设置。终端原生代码此前与主服务共用进程。此证据不足以确认某个上游实现细节是唯一根因。

现在每个终端由独立隐藏辅助进程运行 ConPTY，窗口版 EXE 通过私有启动入口读取继承管道，不启动另一个 HTTP 服务或桌面窗口。主服务先用 Windows 作业对象接管辅助进程，再发送配置；Shell 及后代继承该生命周期。正常结束由操作系统回收辅助进程的原生资源，不在长期服务里执行 PTY 析构。

输入和输出有界排队，另设读写线程，控制线程可在启动超时（10 秒）或原生组件无响应（20 秒）时结束进程树。原有 WebSocket 认证、回放确认、防重、路径核对、尺寸调整和终端 UI 保持可用。

主要源码：`backend/app/terminal_worker.py`、`backend/app/terminal_sessions.py`、`desktop/launcher.py`。
