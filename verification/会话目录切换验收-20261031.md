# 会话工作目录切换验收

范围：Windows 桌面，1440×900 和 1100×700。本批以会话目录切换为范围，不代表整体对标任务完成。

## 本批行为

项目文件 → 工作树中，可将已有会话切换至同一来源项目的可用托管工作树，也可返回来源目录。切换前显示双方目录、分支、完整提交的缩写和改动数量；待确认记录及最近 30 条切换历史保存在 SQLite。关闭审阅可稍后继续，取消会使记录失效。

确认时重新检查会话绑定版本、草稿修订、Git 工作树关系、目录身份、分支、提交、改动列表和活动执行。会话切换、草稿更新、操作完成状态在同一个 SQLite 事务提交。同一记录重试返回原结果；另一窗口已完成不同切换时，旧审阅失效。前台、后台或执行线程尚未结束时拒绝切换；不替用户自动停止任务。

聊天记录、标题、文字/图片草稿、论文、技能、阅读位置保留。相对文件引用清空，由用户在目标目录重新选择。文件编辑草稿保留其明确的原项目 ID，返回原项目后继续编辑；当前只保留一份编辑草稿，不能同时为不同项目编辑多份文件。另一窗口选择保留本地草稿时可保留文字与编辑内容，但不把旧相对文件路径带入新的工作目录。

每次切换递增会话工作目录版本。即使 A → B → A，旧计划、旧前台请求、旧检查点、后台恢复/重跑以及未执行的文件修改、命令和模型 Git 提案仍不能继续写入。新运行与新修改使用当前版本；历史快照保持原归属。分叉保留当前版本，使切换后的有效计划可正常使用，较早的计划继续失效。

## 与完整 Git 迁移的区别

本批仅切换会话的未来执行目录，各目录的 Git 提交、文件、暂存区和终端保持原状。不会清理来源文件，不自动复制或合并改动，也不切换 Git 分支。Git 状态审阅记录提交、分支、路径状态与数量，不是文件内容的逐字节审阅。

完整迁移仍需要：审阅源与目标的提交关系；保存两侧可恢复快照；区分暂存、未暂存、未跟踪及 ignored 文件；处理路径碰撞和合并冲突；协调共享目录的任务/终端；逐步持久化转移与来源清理；进程中断后核对实际内容再继续。不能将本批标为 Codex handoff 已完成。

切换只支持来源项目及应用托管的工作树，不接管其他项目/外部工作树。已归档会话需先恢复；目录已移除或不可访问时，需先恢复工作树。真实模型质量、原生多窗口、原生文件夹选择器和 Codex 像素一致性仍未验证。

## 后续完整迁移的验收门槛

| 场景 | 必须验证的结果 |
| --- | --- |
| 两侧同一提交，目标干净 | 暂存、未暂存、非 ignored 未跟踪内容及二进制字节分别转移；确认前两侧均可审阅和恢复 |
| 目标已有修改或提交分歧 | 显示具体冲突和提交关系；不覆盖目标内容，不以切换会话掩盖迁移失败 |
| 审阅后产生新修改 | 使旧审阅失效，保留后来修改；源和目标都重新检查 |
| 备份、写入、源清理期间中断 | 持久记录每一步；重启核对实际文件与索引后恢复，不能简单重放 Git 命令 |
| 共享目录内另有会话/任务/终端 | 明确受影响对象和协调方式，避免后台执行继续写入待迁移目录 |
