# Git 改动与完整状态迁移 · Windows 桌面验收

本批新增“携带 Git 改动迁移”“携带分支与提交迁移”和对应的返回来源入口，与已有的“切换当前会话到此目录”分别展示。仅做桌面端，验收窗口为 1440×900 和 1100×700。

## 实际支持范围

- 同一来源仓库的来源项目与托管工作树之间，双方 HEAD 相同且目标没有 Git 改动时，迁移暂存、未暂存、非 ignored 未跟踪文件。二进制、非 UTF-8 和换行字节保持原样；同一文件的暂存内容与工作内容分别保留。
- 完整 Git 状态模式要求来源当前签出分支、目标为分离 HEAD；它先把来源工作树分离到目标原提交，再把来源分支交给目标，随后按审阅快照迁移文件和索引。提交分歧不做隐式合并，返回来源时执行反向交接。
- 先备份双方改动路径的前后字节和索引，再写目标文件与索引，最后恢复来源的干净文件与索引。确认前复核目录身份、HEAD、分支、Git 配置、完整文件摘要、索引与受影响会话。目标干净文件的原始内容用于来源的干净版本，Git 换行设置可能使其使用 CRLF。
- 改动迁移模式保持 Git 分支和提交原位；完整状态模式交接来源分支并保留目标原提交为来源的分离 HEAD。目标有改动、ignored 重名或“忽略规则改动且存在 ignored 文件”会在审阅中列出，不会自动覆盖或合并。被忽略文件留在各自目录。
- 双方及祖先/子目录项目中有前台、后台或终端运行时拒绝迁移，用户先结束相关执行。不是自动打断运行的 handoff。
- 会话绑定、受影响会话工作目录版本、草稿更新和完成记录事务提交；旧计划、旧提案和旧请求失效。其他受影响会话保持原目录，文字/图片/阅读/编辑草稿保留，文件引用清空。编辑草稿仍属于原项目。

## 中断与恢复

- 文件/索引写入前持久记录操作位置。成功写入后、来源清理中或绑定前退出，重启均先标记需要核对，不自动重放。
- “核对并继续迁移”仅接受已知迁移前或迁移后的内容。“审阅撤回”再“确认撤回迁移”可恢复双方迁移前状态，会话留在来源。
- 遇到后来修改、外部 Git 刷新后不匹配的原始索引或部分写入后无法识别的字节，保留现场和备份并停止，需要人工核对；不会把未知内容自动当作完成或覆盖。受影响目录在处理完成前暂停应用内操作。
- 使用 Git 锁和 Windows 文件句柄协调；进程退出留下的锁，仅在完整随机标记与持久记录一致时回收，不删除其他 Git 操作的锁。
- ZIP 内的 `review.json`、`operations.json` 给出目录、文件、索引和步骤映射；数字目录中的 `before` / `after` 保存对应内容。Git 私有引用 `refs/scholarflow/workspace-transfers/<记录 ID>/source|target` 保持原暂存对象可达，Git GC 后仍可撤回。**ZIP 依赖原 Git 仓库，不是完整仓库备份。**

## 使用步骤

1. 在项目文件面板打开“工作树”，选择“携带 Git 改动迁移”。
2. 核对双方目录、提交、文件范围和受影响会话，确认目标可接收改动。
3. 点击“备份并确认迁移”，完成后会话在目标继续。
4. 若响应丢失，重试同一记录；若中断，在“有待处理的 Git 改动迁移”中继续或审阅撤回。
5. 在目标点击“携带改动返回来源”或“携带分支与提交返回来源”，可按相同规则返回。

## 仍有差距

- 完整状态模式已迁移本地分支指向、未推送提交和双方工作区/索引快照；仍不自动合并提交分歧，也不处理远程同步、冲突解决器或完整仓库复制。
- 现有扫描上限为每个目录 10,000 文件、512 MiB，单次最多 1,000 个改动路径。链接、联接、嵌套仓库、子模块、特殊/冲突/拆分索引、意向添加和文件/目录冲突需先在外部 Git 工具处理。
