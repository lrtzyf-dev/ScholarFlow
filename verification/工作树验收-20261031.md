# Windows 桌面：工作树管理

范围为 1440×900 和 1100×700。程序位于 `desktop/ScholarFlow/ScholarFlow.exe`，独立验收包为 `研序ScholarFlow-桌面验收版-20261031-工作树管理.zip`。

## 使用步骤

1. 在侧栏添加一个已有提交的本地 Git 项目，打开聊天输入区的“项目文件”，切换到“工作树”。本机需安装 Git。
2. 点击“创建工作树”，填写名称及起始本地引用/提交。可填新的分支名；留空则使用分离 HEAD。来源项目的未提交文件不会复制过去。
3. 在新工作树点击“在此新建会话”。它有独立工作文件和暂存区，共享 Git 提交记录；原来的会话仍绑定来源项目。
4. 完成工作后先提交或移出未保存内容，结束该目录中的任务和终端，点击“审阅移除”。确认后移除工作目录，同时保留提交、分支、项目和聊天记录。
5. 在“已移除”中选择“恢复工作树”，恢复到原目录的分离 HEAD。项目和聊天记录继续可用；目录身份已变化，旧执行检查点需重新核对，不自动改绑。

## 本批处理

- 创建前解析本地提交；保存请求编号防止响应丢失后重复创建。创建草稿与未确认请求持久化，两个窗口用修订号处理冲突。
- 移除仅面向应用创建的工作树。再次核对目录身份、审阅修订、分支和 HEAD；有未提交、未跟踪、被忽略文件或跳过文件检查的索引标记时拒绝移除。
- 前台执行、后台任务、子目录项目和终端仍活动时拒绝移除。子模块、Git 锁定目录及被替换的管理目录均拒绝。
- 移除前创建 `refs/scholarflow/worktrees/<id>`，避免分离 HEAD 或未推送提交因目录移除而失去可达引用。
- 中断后不自动重放 Git。核对已完成创建、已完成移除，或重新接入仍存在的原目录；移除失败后迟到的用户修改会保留。
- 修复 1100×700 下创建按钮被对话框底部遮挡的问题，改为面板内部滚动，并验证按钮中心实际可点击。复查截图发现未定义边框变量，改用现有主题令牌恢复输入框/按钮边界；创建时收起工作树列表，让表单在桌面面板内完整呈现。

## 仍有的差距

本批只支持干净工作树的移除与恢复。Codex 的归档还保存本地未提交修改及非 ignored 的未跟踪文件；这一快照归档能力仍需开发。现有会话迁移、远程同步、模型工作树工具、接管外部工作树也未实现。

| 能力 | 当前 Codex 工具说明 | 研序当前实现 |
| --- | --- | --- |
| 从指定提交创建 | 分离 HEAD，不复制未提交内容 | 已实现；另可指定新分支 |
| 与聊天的关系 | 创建/附加托管目录到当前聊天 | 注册独立项目并新建会话；旧会话保持原目录 |
| 归档本地改动 | 快照保留本地修改、未推送提交和非 ignored 未跟踪文件 | 只保留提交引用；有未保存文件时拒绝移除 |
| 恢复目录 | 原路径、分离 HEAD；原未提交内容在快照提交中 | 原路径、分离 HEAD；仅恢复先前已提交内容 |
| 接入已有托管目录 | 可附加而不 reset | 外部工作树仅只读列出；中断记录可核对接入原目录 |

恢复依赖原来源仓库和管理目录，不能作为独立备份。Git 文件/索引隔离不限制命令或外部工具的系统访问，也不能完全隔离外部 Git 并发操作。

对标方向依据本机 Codex 暴露的工作树工具说明及 Git 官方文档。本机 Computer Use 原生管道仍不可用，未取得新的 Codex 原生界面截图；本批浏览器与 EXE HTTP/进程验收不代表原生输入法、系统剪贴板、窗口正常关闭或像素级一致性已经通过。
