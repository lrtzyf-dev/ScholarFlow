研序 ScholarFlow vs Codex：能力差距分析

以成熟 agent 产品 OpenAI Codex 为标杆，对照 ScholarFlow 现状。结论：基础智能层（流式思考、MCP/技能、引用证据、语义审计、去重、记忆、入库）已对齐；真正的短板集中在 “可控性”（审批）、“可规划”（任务拆解）、“可恢复”（断点续跑）、“可并行”（子 agent） 这四件成熟 agent 的骨架能力上。

能力对比矩阵

补什么、按什么顺序（科研场景转化）

P0 · 决定像不像成熟 agent先做
人工审批节点
对应 Codex 三级审批。工具按风险分级：只读检索直接执行；外联/下载/入库/删除前弹审批卡，可选“仅一次 / 本会话始终允许”。
任务规划与待办
对应 Codex to-do list。“写综述”先拆：检索→去重→主题聚类→起草→引用审计→定稿，逐项点亮，进度可见。
上下文压缩
对应 compaction。近期保留原文、早期自动摘要，长会话不超 token 且不丢关键结论。
P1 · 拉开差距、强体验其次
断点续跑
对应 codex resume。长综述/批量入库任务落盘，关闭后从断点继续，新增任务列表页。
多模态输入
对应 图片/截图输入。上传图表、实验图、手写笔记、论文截图，可就图提问与图表解读。
子 agent 并行
对应 subagents/并行。综述时按子主题并行派“专题检索子 agent”，主 agent 汇总；批量文献并行摘要。
我的工作规范
对应 AGENTS.md。可写“课题组写作规范/引用格式/语言要求”，持久注入每个任务。
P2 · 商业化 / 完整度随后
一键审我的稿件
对应 code review。上传自己的综述/草稿，做审稿人式审查：论断有无引用、引用是否真实、逻辑漏洞。
产物自检闭环
综述定稿前自动核对：每条论断有证据、引用与参考文献一一对应、关键文献无遗漏，出校验报告。
多格式导出
综述导出 Word / Markdown，参考文献导出 BibTeX / RIS，便于直接投稿。
云同步 / 多设备
对应 云任务/团队共享环境。属 SaaS 商业化阶段，本地版先不做。

建议落地顺序：先做 P0 三件（审批、规划、压缩）——它们让 ScholarFlow 从“能对话”升级为“可托付的 agent”，也是比赛答辩最能体现工程深度的部分；P1 视时间补“断点续跑 + 子 agent 并行”，演示效果最直观。
